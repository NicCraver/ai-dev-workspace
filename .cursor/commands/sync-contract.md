# 后端接口更新后同步契约文件并排查四端影响

接口契约同步任务。用户输入：$ARGUMENTS

1. **更新契约**：根据用户提供的最新接口信息（文档片段、抓包结果或口述），更新 `context/contracts/` 下对应文件。在文件头部 Changelog 追加一条：日期 + 变更点（新增字段 / 类型变化 / 语义变化 / 废弃）。
2. **影响面分析**：对每个变更点，用 codebase-memory 在四端仓库中检索使用该接口/字段的位置，输出影响矩阵：

   | 变更点 | web | android | ios | desktop |
   |--------|-----|---------|-----|---------|

   标注每处是"需改代码 / 仅需回归 / 不受影响"。
3. **同步文档**：把需要改代码的项写入活跃功能 `status.md` 的「待办 / 阻塞」小节（每端一条）。
4. 询问用户是否现在就修改某个端的调用代码；如果是，从 web 端开始。完成后走 wrapup。

原则：**永远先改契约、再改代码**。契约与实际接口不一致是四端不一致 bug 的最大来源。
