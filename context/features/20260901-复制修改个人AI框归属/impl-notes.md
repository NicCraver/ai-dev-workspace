# Impl Notes：复制修改个人AI框归属

> 平台无关的实现笔记，是其他端移植的唯一逻辑依据。web 端联调完成后必须填写。
> 写法要求：描述"逻辑"而不是"代码"——禁止出现 React/Kotlin/Swift 的具体 API。

## 状态流转

回填分类见 spec。本条补充输入框退格与 @ 区间：

- chip = `@` + 显示名 + 尾部空格（与插入 @ 时写入的文案一致）
- 高亮 / mention 区块只覆盖 chip，不得把后面普通正文算进去
- 退格删正文（例如 `@姓名 测试1` 删「1」）→ 只少一个字；chip 与筛选条不变
- 退格发生在 chip 末尾（通常是姓名后的空格），即使后面还有正文 → 整颗去掉 chip，并关掉智能体筛选条（若输入区已无其它智能体 @）

## 接口调用时序

无。退格与区间收缩是纯输入框逻辑。

## 边界情况

- extra / 草稿里的 start/end 比 chip 长（把「测试1」算进 @）→ 回填时按显示名把区间收到 chip；不要信任过长下标
- 输入时后一个字继承了 @ 的高亮属性，区间被撑大 → 新输入应使用普通文本样式；退格仍按 chip 末尾判断，不要按「被撑大后的区间末尾」整删
- 光标在 chip 与正文之间（紧贴空格）且正文还在 → 整删 chip，留下正文
- 多端 DOM / 隐藏占位节点（PC 的 hideSpan）不能当成「输入区只剩一个 @」

## 错误处理策略

宁可不整删 @，也不要把删正文误判成删 @。筛选条只在智能体 mention 真正从输入区消失后关掉。

## 联调坑（实际接口 ≠ 文档之处）

- 消息 extra 的 at 下标有时覆盖整段复制内容，不只是 `@姓名 `
- iOS extra.atUserList 不带 agentKind（与回填分类同一坑，见 spec）
