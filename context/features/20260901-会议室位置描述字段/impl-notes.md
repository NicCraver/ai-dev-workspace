# impl-notes：会议室位置描述

平台无关。`locationDesc` 与 `locationNote` 是两个字段，不要互相覆盖。

## 字段

| 字段 | 用途 | 上限 | 空值 |
|------|------|------|------|
| `locationDesc` | 怎么找到这间屋子 | 50 字 | 空白规范化成「没有」 |
| `locationNote` | 投影线、使用须知等通用备注 | 100 字 | 各存各的 |

超长 → 业务校验失败（码 `M4000`，文案「位置描述不超过 50 个字」）。

Java 实体对可清空字段用「空也写入」策略，否则全局「非空才更新」会让用户清不掉已填描述。

## 读写路径

管理端创建/更新会议室时带上该字段；列表、看板房间、房间详情原样回显。看板与房间详情只展示有内容的描述，不要把备注栏改成位置指引。

本机联调（2026-09-01）：管理端新建房间填「联调1层东侧」，改成「联调1层西侧」后再打开能看到新值。数据在 contact MySQL，不是 Node SQLite。

## 联调坑

- 前端请求 base 仍是会议室网关前缀，开发代理把非助手路径改写成 Java `/meetingRoom`。
- Node SQLite 与 Java MySQL 不是同一份数据；种子房的示例描述不能当 Java 验收基准。
