# Impl Notes：安卓 ActionCard 卡片内容被截断

> 平台无关的实现提炼。最后更新：2026-08-20（进行中）
> 本功能是纯渲染层缺陷修复，无接口、无 bridge、无状态机，故不套模板的时序 / 状态流转小节。

## 1. 折叠判定不能依赖「回调时子 View 已测量完」

聊天列表里的长卡片要在超过限高时折叠并显示展开入口。安卓实现有两层：

- **当帧硬夹**：绑定时立刻把容器外框高度顶在限高上。这是为了避免容器先以完整高度（长回复实测 4.8 万 px）参与一次布局——否则列表内容总高暴涨再塌回，视口被顶飞，表现为翻历史被拽回最新卡片。
- **精修折叠**：等测量完成后再按段取舍，决定裁在哪、显不显示「查看更多」。

原实现把第二层放在「下一帧回调里累加子 View 的测量高度」。**含横滚容器的段（表格）在那个时刻可能还没完成有效测量**，累加得到 0，判成「不需折叠」，于是：按钮不显示，而第一层的硬夹**没有被复位**，卡片被夹死且无展开入口。

**教训（跨端通用）**：夹高与判定是两件事，判定必须基于「内容真实高度」的可靠来源，且必须满足这条不变量——

> **判定为「不需折叠」时，必须同时撤销硬夹。** 少了这半句，失败模式就是「内容被切、没有出口」。

做法：容器在测量时自己记录**夹高之前**的真实高度，判定用它；测量完成后主动上报判定结果，调用方只负责显 / 隐按钮。

配套细节：**折叠之后测到的高度不是内容全高**（子段被隐藏或截断），不能拿去更新「真实高度」，否则下一轮判定会翻成「不需折叠」，把刚折起来的卡片又展平、按钮消失。用一个「已折叠」标志把两种状态隔开。

## 2. 折叠入口不止一个，漏一个就等于没修

同一条消息可能通过四条路径进入折叠 / 展开：气泡首次绑定、气泡上的展开与收起按钮、列表右侧悬浮的「收起内容」、引用聚合列表里的首条源消息。每条都得走同一套判定与同一条不变量。

已踩：其中两条只调整了「纯文本控件」的限高，对「含表格走另一套容器」的消息完全无效——表现为点了没反应 / 展不开。

## 3. 知识来源尾段的两个独立缺陷

AI 回复正文里用引用标签标注出处，卡片末尾再列一份「知识来源」清单。清单的构造规则是：**只保留正文里真正引用过的文档**（按首次出现排序）。

真机日志暴露两个问题：

1. **引用标签的 id 与文档清单的 id 不同体系**时（实测正文写 `toutiao_article`，清单里全是另一套 id），过滤结果为空，整份知识来源消失。→ 过滤命中为空时应退回全量展示，而不是丢弃。
2. **清单文本已经拼进最终文本、条数正确，但屏幕上看不到**。说明不是数据丢失，是布局 / 绘制层面的问题，定位仍在进行（下一轮看展开后文本控件的行数与 layout 高度）。

> 通用教训：「尾部内容看不见」先分清是**没拼进去**还是**没画出来**——两者修法完全不同。一行「最终文本长度 + 尾部 20 字 + 条目数」的日志就能分开，比读代码猜快得多。

## 4. 真机排查的环境限制（安卓）

- 该测试机禁止 adb 注入输入事件（`INJECT_EVENTS` 权限），无法脚本化点击 / 滑动，界面操作必须人工。
- 截图 / logcat / 安装可用。所以排查手段优先选「代码自己打日志」，而不是「驱动界面复现」。

## 联调坑（实际接口 ≠ 文档之处）

- 引用标签 `data-ref` 的取值与 `agentKnowledgeList[].docId` **不保证同体系**（实测存在 `toutiao_article` 这类字面量）。任何按 docId 精确匹配来过滤知识来源的实现都会在这种消息上丢内容。契约未记录此差异，其他端若有同样的过滤逻辑需一并检查。
