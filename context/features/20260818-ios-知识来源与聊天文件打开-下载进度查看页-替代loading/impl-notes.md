# Impl Notes：打开文件的下载进度与取消

> 平台无关的逻辑提炼，供其它端移植参考。最后更新：2026-08-18（iOS + web 代码完成，未真机自测）

## 问题与结论

点开一个远端文件时，原实现全程只有一个不确定态转圈（iOS `ZXProgressHUD`）。大文件下载几十秒到几分钟，用户既看不到进展也无法中止，观感等同卡死。

结论：**不需要安卓那样的独立「文件查看页」**。真正缺的是两件事——① 真实百分比；② 取消。把已有的加载浮层升级即可。

## 关键结构：所有入口收敛到一个下载点

三条链路（AI 卡片知识来源 / 聊天文件消息 / H5 知识来源）最终都调同一个「下载到沙盒再预览」的方法。因此**进度与取消能力加在下载层**，各入口只负责创建会话、接回调。移植到其它端时先找到这个收敛点，别在每个入口各写一套。

iOS 对应关系：

| 链路 | 入口 | 收敛点 |
|------|------|--------|
| AI 卡片知识来源 | `ZXAgentKnowledgeOpenLogic openItem:` | `ZXFileClient writeToFile:progress:completion:` |
| 聊天文件消息（普通 / 加密 / 微应用分享） | `ZXMultiMediaClient multiMediaPreviewFile:` → `openLocalFile:` | 同上 |
| H5 知识来源 | 桥 `openKnowledgeDoc` → `openItem:` | 同上 |

## 三段式进度模型

一次打开由「不确定阶段」和「可测量阶段」拼成。规则：

1. **前置阶段 0 → 8%**：元数据接口 + OSS 签名。没有真实进度，用定时器每 0.5s 前进 1%，8% 封顶（只为消除"卡住"观感，不假装快）。
2. **下载阶段 8% → 100%**：真实字节进度 `fractionCompleted`，线性映射到 `[0.08, 1.0]`。
3. **加密文件（绿盾）**：解密任务轮询沿用原有 5% → 65% 的阶段值，下载段起点改为 65%，映射到 `[0.65, 1.0]`。
4. **单调保护**：展示层只接受 `max(已展示, 新值)`，多段拼接不会回退。
5. **收尾**：到 100% 停 0.25s 再关浮层弹预览，避免"99% 突然消失"。

## 取消语义

- 取消 = 会话置 `cancelled` → **中止下载任务** + **删除半成品文件** + 关浮层。
- 置位后所有在途回调（元数据、签名、下载完成、解密轮询）一律**直接丢弃**，不弹 toast（用户主动行为，无需解释）。
- **不做**断点续传 / 暂停继续 / 后台下载。下次点开重新下载。
- 解密轮询没有可中止的网络句柄，取消只能靠丢回调 + 关浮层，轮询自然结束。这点在其它端同样适用：**能 cancel 的 cancel，不能 cancel 的用状态位挡住回调**。
- 半成品必须删：否则下次"本地已存在"判断命中坏文件，直接打不开且很难排查。

## 会话对象（推荐抽象）

把「浮层 + 假进度定时器 + 阶段映射 + 取消聚合」收进一个短生命周期对象，各入口只用 5 个动作：

- `start(title)`：展示浮层，启动前置假进度
- `onCancel = block`：挂中止动作（可叠加：下载 cancel + 状态回报）
- `updatePollingProgress(p)` / `updateDownloadProgress(p)`：两种阶段的进度入口
- `finish(completion)`：补到 100% 后回调（在回调里才弹预览）
- `dismiss()`：失败或不再需要

iOS 落在 `ZXFilePreviewLoadHUD.h/.m` 里的 `ZXFileLoadingSession`（**故意不新建文件**，避开 `project.pbxproj` 改动带来的排序噪声与漏加 target）。

## 结束状态回报（给 JSBridge 用）

原生打开流程结束时回报三态之一，且**只回报一次**（用 `finishReported` 幂等）：

- `success`：预览已弹出（含外链 / 智文 Web 页 / 图片浏览器）
- `cancel`：用户点取消；**飞书 / WPS 未授权也算 cancel**（原生已拉起授权页，本次打开未完成，web 不必处理）
- `fail`：接口错误 / 签名失败 / 下载失败 / 预览失败（原生已 toast）

桥协议见 `context/bridge.md` 的 `openKnowledgeDoc`。

## 平台降级

新桥只有 iOS 实现。web 按 UA 判断容器（`MTCoreApi` + iPhone/iPad/iPod），非 iOS 客户端保持原逻辑不动。判断与参数构造抽成纯函数 `knowledgeNativeOpen.js`，有单测；**别把平台判断散进组件**。

## 自测观察点（已知可能不完美，需真机确认）

- **加密文件二段浮层**：解密段结束 → 浮层补到 100% 关闭 → 若接着还要下载，会再起一个新浮层从 2% 开始。观感上是"100% 后又从头"。真机确认是否刺眼，刺眼再改成同一会话贯穿。
- 本地已缓存的文件不应出现浮层（走 `readFile` 命中分支，直接预览）。
- 取消后立刻重新点开，应能重新下载（半成品已删）。
