# Impl Notes：智能体仿流式输出抗抖（平台无关提炼）

> 安卓实现在 `IM/dialogue/agent_stream/`（新包）+ `ReferenceMessageItemProvider` + `ConversationFragment`。
> 其它端要做同样的事时按本文的逻辑走，不要照抄安卓 View 代码。

## 一、数据链路

```
每 2s 轮询 aiRobtMessageById(msgUID) → 拿到「整篇」最新答案（不是增量）
        ↓ 存进 uid → 全文 的 map，广播一条「该 uid 内容变了」
会话页收到广播 → 找到该 uid 对应的可见 item → 交给它自己去追
        ↓
本地打字机：每 150ms 追一步，每步 ≥10 字，把当前欠的字数摊进 1500ms 跑完
```

要点：**服务端给的是全文快照，本地负责把「快照差」演成流式**。
所以本地必须自己维护「已显示到哪」（`itemShowAgentAnswer`），
并且每次刷新只是把「目标」变长，不是重新开始播。

## 二、四个抖动源（按影响从大到小）

1. **打字机是全局单例上的一个定时器。**
   provider（item 渲染器）在这套 IM 框架里是每种消息类型一个全局实例，
   把 Handler + Runnable 挂在它身上，等于全 App 只有一条打字机时间线：
   - 另一条智能体回答刷新 → `removeCallbacks` 掐掉前一条；
   - **任何一条普通引用消息重新绑定**（滚动、任何 notifyItemChanged）也会 `cancelStream()`；
   被掐掉后要等下一次 2s 轮询才重启，于是文字一顿一顿地蹦。
   → 改成**按消息 uid 各自排队**，互不干扰。

2. **跟随滚动慢一拍 + 自己跟自己打架。**
   - 在 `setText` 当场读 item 的 bottom：那时本帧布局还没跑，读到的是旧值 → 永远滚少一步；
   - 用「平滑滚动」：列表进入 SETTLING 状态，而跟随逻辑又有「非 IDLE 就不抢滚动权」的保护，
     下一步就被自己造成的 SETTLING 挡掉 → 走走停停。
   → 把滚动**推迟到本帧布局完成后、绘制之前**再算，并用**瞬时滚动**。
   每步只多一两行，瞬时滚看着才是连续跟随。

3. **每帧整篇重新解析 markdown。**
   150ms 一帧、每帧把已显示的全文重新 parse + 建 span，代价随答案长度线性增长，
   长回答后半段单帧就可能超一帧预算 → 掉帧放大抖动观感。
   → 缓存「稳定前缀」的渲染结果：多数帧只是尾行多了几个字、前缀边界没动，直接复用，
   只把未成型的尾巴按纯文本拼上去。缓存键 = uid + 前缀长度 + 前缀内容指纹。

4. **半成品 markdown 的结构跳变**（上一轮已修，保留）：
   按字符硬切的切点是随机的，`| 表头 |` 这帧是普通文字、分隔行到了下一帧整块变表格，
   `**粗体` 闭合前后字重和折行全变 → 高度剧变。
   → 只把「最后一个完整行」之前当 markdown 渲染；若最后一块是「有 `|` 但还没出现
   分隔行」的半张表，整块退回纯文本，等分隔行到了再让它成为表格。

## 三、复用列表控件时的护栏

- **holder 复用**：打字机持有的是某个具体 item View。列表把这个 View 复用给别的消息后，
  定时器还在往上面写 → 画到别人身上。
  → item 上记「我当前属于哪条消息 uid」，打字机每步先核对，不匹配就地停掉；
  View 已经从窗口上摘掉也停。
- **高度只增不减**：半成品的行数会来回抖，容器跟着缩会把列表拽一下。
  流式期间给文本容器一个「不低于当前高度」的地板。
  **地板必须在下一条消息绑定时清掉**，否则短消息会被撑高（复用泄漏）。
- **只有列表最后一条才跟随滚动**：否则翻历史时中间某条回答会把你反复拽回去。

## 四、手感参数（四端保持一致）

| 参数 | 值 | 含义 |
|------|----|------|
| 轮询间隔 | 2000ms | 拉一次全文快照 |
| 仿流式时长 | 1500ms | 当前欠的字数摊进这段时间吐完 |
| 最小帧间隔 | 150ms | 一步一帧 |
| 最小步长 | 10 字 | 每步至少吐这么多，避免一个字一个字磨 |

补充：切字时**不要把代理对（emoji）从中间切开**，否则会闪一帧乱码方块。

## 五、联调坑

- 轮询接口在答案结束后**不会自己停**，仍每 2s 回一次相同全文；靠「座位消息被撤回」
  才 `removePollingAgentAnswer`。所以刷新回调里必须先比「内容有没有真的变长」，
  没变长就直接 return，不能无脑重渲染。
- 「回答中」和「回答完成」是两条不同的消息：进行中是引用消息（流式座位），
  完成后座位被撤回、另发一条 AI 卡片。定位问题时先确认手上那条是哪种，
  否则会改到不生效的那一条链路上。
