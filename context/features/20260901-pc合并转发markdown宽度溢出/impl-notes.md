# Impl Notes：合并转发详情里 markdown 宽表溢出

> 平台无关。最后更新：2026-09-01

## 现象

同一条带表格的智能体卡片：会话气泡里正常折行、表可横滚；放进合并转发（聊天记录）后再打开，整卡右侧被裁掉，表也滑不了。

## 根因

气泡宽度必须由**窗口列宽**决定，不能被表格的内容宽撑开。宽表自己在气泡里横滚。

会话列表已经锁了这层。合并转发详情、回复列表是另两套克隆气泡，当时只抄了 `overflow: hidden`，没抄「允许缩到父级」。结果是：

1. 表按内容变宽，把气泡撑出窗口
2. 外层再把超出部分裁掉
3. 表的滚动容器和气泡一样宽，看起来就像没有横滚

正文段落也会一起被裁——它们是按撑开后的气泡宽度折行的，窗口里只看得到左半截。

## 修法

每套气泡克隆都要在「头像旁的消息列」和「白底气泡」上锁：

- 消息列允许缩到父级（不要按内容设下限）
- 气泡宽度不超过这一列

表格仍用既有横滚容器，不要改成把表压进一列或禁止变宽。

## 边界

| 场景 | 预期 |
|------|------|
| 会话列表里的原消息 | 本来就不溢，别动那条链路 |
| 合并转发详情 | 卡贴列宽，宽表横滚 |
| 回复列表里的同类卡片 | 同一套锁，避免再漏 |
| 窄表 | 无横条，气泡不被强行拉满 |
| 自己发的淡蓝气泡 | 同一套管线，不单独配色 |

## 与 bridge 的交互

无。
