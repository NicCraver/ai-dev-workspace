# Impl Notes：合并转发详情里 markdown 宽表溢出

> 平台无关。最后更新：2026-09-01

## 现象

同一条带表格的智能体卡片：会话气泡里正常折行、表可横滚；放进合并转发（聊天记录）后再打开，整卡右侧被裁掉，表也滑不了。段落看起来像没换行，其实是按「被表撑开后的气泡宽」折的，窗口里只看得到左半截。

## 根因

气泡宽度必须由**窗口列宽**决定，不能被表格的内容宽撑开。宽表自己在气泡里横滚。

会话列表已经锁了消息列。合并转发详情、回复列表是另两套克隆气泡。漏了两层：

1. **头像旁的消息列**没允许缩到父级，表按内容把列撑出窗口
2. **包着白底气泡的那一行**（会话列表里也有，用来摆发送态/失败图标）同样是横向弹性布局。缺「允许缩到列宽」时，这一行的下限仍是表的最小内容宽。外层再 `overflow: hidden`，看起来就像没有横滚

表的滚动容器如果只写「不超过父级、自己可横滚」，但父级已经被表撑得一样宽，容器判定「没溢出」，横条不会出现。外壳必须**跟着已经锁死的列宽走**，表按内容变宽，两者之差才是横条。

正文段落被裁，是同一件事：它们在撑开后的宽度里换行，窗口裁掉右半截。

## 修法

每套气泡克隆都要锁：

- 头像不参与收缩
- 消息列吃掉头像后的剩余宽，并允许缩到比表的最小内容宽更窄
- 包着气泡的那一行同样允许缩到列宽
- 白底气泡不超过这一列
- 卡片本身不要设最小宽度下限（下限会顶住缩窄）
- 表格滚动外壳跟着列宽走；表仍按内容变宽，不要改成整表压进一列

不要重写 markdown 管线，不要禁止表变宽。

## 边界

| 场景 | 预期 |
|------|------|
| 会话列表里的原消息 | 本来就不溢；补同一行的收缩锁，避免再漏 |
| 合并转发详情 | 卡贴列宽，正文折行，宽表横滚 |
| 回复列表里的同类卡片 | 同一套锁 |
| 窄表 | 无横条，气泡不被强行拉满 |
| 自己发的淡蓝气泡 | 同一套管线，不单独配色 |
