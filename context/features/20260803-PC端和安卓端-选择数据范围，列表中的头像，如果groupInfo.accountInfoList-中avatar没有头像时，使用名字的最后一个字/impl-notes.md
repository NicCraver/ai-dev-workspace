# Impl Notes：选择数据范围 · 群拼图无头像用名字末字

> 平台无关。最后更新：2026-08-03

## 状态流转

无新状态机。仅改变群拼图格子的展示：打开数据范围页后，候选归一化即带上前 4 人成员信息；勾选/保存链路不变。

## 接口调用时序

沿用既有：开页 `getAllImDialogue` + `getAgentDataRange`。不新增接口、不改契约。成员 `id` / `nickName` / `avatar` 来自回参 `groupInfo.accountInfoList`。

## 显示规则（移植必遵）

1. 取 `accountInfoList` 前 4 人，顺序不变。
2. 归一化保留成员对象 `{ id, nickName, avatar }`（可派生 URL 列表，但渲染必须以对象为准）。
3. 单格优先级：有 avatar → 图；否则有 nickName → 末字（trim 后最后一字符）；否则默认人像。
4. URL 加载失败视为无有效图，再走末字/默认图。
5. 无 avatar 的成员**不得从拼图中剔除**，否则 1～4 人格局会塌缩。
6. 名字只用接口 `nickName`，不查本地通讯录。
7. 1～4 人布局与现网一致；缺右下空位底色本期不改（Desktop/Android 为浅灰 `#f3f3f3`）。

## 覆盖面

主列表、搜索结果、底栏已选 chip：凡群拼图均走同一套规则。

## 边界情况

| 场景 | 预期 |
|------|------|
| avatar 空、nickName 有 | 该格末字 |
| 都空 | 默认人像，不裂图 |
| 仅 3 人 | 缺右下；空位底色不变 |
| 成员列表空 | 整圆默认群头像（与现网一致） |
| 私聊行 | 本期不改 |

## 错误处理策略

头像 URL 加载失败：按「无有效图」处理，有 nickName 则末字，否则默认图。不影响勾选与保存。

## 联调坑

- 旧实现若先过滤空 avatar 再拼图，格数会塌缩；必须保留空 URL 占位再画末字。
- （真机手测后补：加载失败 / 已选弹层缓存是否与列表一致）

## 与 bridge 的交互

无（Desktop / Android 原生页直接展示；不改桥协议）。
