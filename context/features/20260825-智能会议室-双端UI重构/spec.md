# Spec：智能会议室 · 管理端与预定端 UI 重构

> Superpowers brainstorm 产出。最后更新：2026-08-25

## 背景与目标

`apps/meeting/designs/` 已有会议室管理端和会议室预定端两套可交互原型，但目前存在以下问题：

- 两端视觉令牌重复，组件风格和房间字段命名不完全一致。
- 管理端增加了需求范围外的“字典表”一级模块，建筑、设施与会议室数据形成双数据源。
- 预定端同时承载移动端卡片、桌面时间轴和多个弹层，页面层级及状态管理偏重。
- 加载、失败、冲突、身份失效等关键状态覆盖不完整。

本次重构仅更新 `designs/` 中的设计原型，不改变当前“会议室管理 P0”的业务实施范围，也不直接修改 `web/` 或 `server/`。目标是形成一套可供后续 Vue 业务页面落地的统一 UI/UX 基线。

成功标准：

1. 管理端与预定端共享同一套品牌令牌、字段语义和反馈规范。
2. 管理端完成列表、新建、编辑和启停的高效闭环，不保留独立字典表。
3. 预定端在移动与桌面形态下均能完成找房、选时段、确认预定、查看及释放预定。
4. 两端覆盖主要加载、空、失败、冲突和成功状态。
5. 原型在 390px、1280px、1440px 视口下结构完整、操作可达。

## 设计原则

采用“安静的效率工作台”方向：

- 现代企业效率工具气质：克制、清晰、专业，不追求装饰性大屏效果。
- 两端共用设计系统，但保留各自任务最合适的页面壳和信息密度。
- 以日期、房间和时段为核心对象；避免无数据支撑的运营概览。
- 主要依靠间距、边框和浅色分区建立层级，减少大阴影、渐变和卡片嵌套。
- 保留用户上下文：返回后恢复筛选、日期、分页、滚动位置和未完成选择。

## 信息架构

### 管理端

取消左侧导航和字典表，使用轻量顶栏：

```text
会议室列表
├── 搜索与筛选
├── 会议室表格
├── 新建会议室
├── 编辑会议室
└── 停用 / 启用
```

- 列表页承担名称搜索、状态筛选、建筑/楼层联动、分页和启停操作。
- 新建与编辑使用同一表单，按“基本信息、设施、预定规则、备注”分区。
- 建筑、楼层使用“可搜索、可创建”的组合框；设施固定为五项枚举。

### 预定端

移动端：

```text
日期与筛选 → 可用会议室 → 房间详情 / 时段选择 → 预定确认
                                      └── 我的预定 → 释放
```

- 首页优先展示当天可用性和每个房间最近可预定时段。
- 完整时段进入房间详情后查看，选中时段后由底部操作区持续反馈。
- 筛选、预定确认、我的预定与释放确认使用符合移动端习惯的底部面板或全屏页。

桌面端：

- 保留多会议室时间轴。
- 日期、筛选、图例和“我的预定”收敛到单一工具栏。
- 房间信息固定在左侧，时间轴负责可用性与时段选择。
- 预定详情和创建流程使用右侧抽屉，避免离开当前时间轴上下文。

## 视觉系统

- 主色沿用智信蓝 `#3E7EFF`；中性冷灰作为画布和分隔色。
- 绿色只表示可用或启用，橙色表示待确认，红色只用于错误和破坏操作。
- 桌面正文以 14px 为主，页面标题 20–24px；移动触控控件使用更宽松尺寸。
- 输入与按钮圆角 6px，卡片、抽屉和面板圆角 10px；不使用大面积胶囊化。
- 内容层级以 1px 边框、浅色分区和间距为主，阴影只用于浮层。
- 管理表格保持紧凑；预定卡片和移动触控区域保持舒展。

## 关键交互

### 管理端

- 名称搜索使用 300ms 防抖；建筑和楼层级联。
- 当前筛选可单项清除，重置操作保持可见。
- 表格行可进入编辑，同时保留明确的“编辑 / 停用”操作。
- 停用需要二次确认；启用直接执行，重名时给出明确失败反馈。
- 表单实时校验基础格式，提交失败后定位并聚焦首个错误。
- 仅在存在未保存改动时拦截离开；固定保存栏持续展示提交状态。

### 预定端

- 先选择日期，再筛选位置、人数和设施，结果实时反映当天可用性。
- 时段选择采用“先开始、再结束”的明确两步，并持续显示时长。
- 不可用区间不可选择，同时说明占用或规则限制原因。
- 移动端使用底部面板确认，桌面端使用右侧抽屉确认，两端字段和校验一致。
- 提交前再次校验冲突；冲突时保留用户输入并刷新可用时段。
- 我的预定按“即将开始 / 历史记录”分组；释放需要确认。

## 状态与反馈

两端统一覆盖：

- 首次加载与局部刷新。
- 无数据与筛选无结果。
- 网络失败、身份失效和记录不存在。
- 表单校验失败、名称冲突和时段冲突。
- 保存或预定进行中、操作成功和破坏操作确认。

Toast 只承担短暂结果反馈，不作为表单错误或长期状态的唯一载体。确认弹窗默认焦点放在取消或安全操作上，关闭后焦点返回触发元素。

## 组件与数据边界

建议目录职责：

```text
designs/
├── shared/
│   ├── tokens.css
│   ├── base.css
│   └── room-schema.jsx
├── zhixin-meeting-room/
│   ├── app.jsx
│   ├── components-shared.jsx
│   ├── components-list.jsx
│   └── components-form.jsx
└── zhixin-meeting-mobile/
    ├── app.jsx
    ├── components-shared.jsx
    ├── components-mobile.jsx
    ├── components-desktop.jsx
    ├── mobile-timeline.jsx
    └── pc-timeline.jsx
```

- `shared/` 只共享稳定的设计令牌、基础样式和房间字段定义，不强行共享平台特有布局组件。
- 两端统一 Room 字段名、设施枚举和状态语义。
- 预定事件独立于会议室主数据，避免把忙闲事件写入房间基础字段。
- 页面状态按领域数据、筛选、选择、弹层和提交状态分离，降低 `app.jsx` 的总控复杂度。

## 范围

本次做：

- 重构 `designs/zhixin-meeting-room/`。
- 重构 `designs/zhixin-meeting-mobile/` 的移动和桌面形态。
- 新增 `designs/shared/` 共享设计基线。
- 删除管理端字典页面及其状态、本地存储和入口。
- 对齐两端房间模型、设施枚举、状态与反馈。

本次不做：

- 不修改 `web/`、`server/`、接口契约或原生宿主。
- 不将预定功能加入当前会议室管理 P0 的正式开发范围。
- 不新增运营数据大屏、审批流、周期预定或抢占引擎。
- 不新增建筑、楼层、分组或设施的独立 CRUD。
- 不引入新的前端构建工具或 UI 依赖。

## 验证方案

- 管理端：筛选、联动、新建、编辑、校验、启停、脏表单返回、空态和失败态。
- 预定端：日期与条件筛选、选择空闲时段、冲突处理、提交、查看与释放预定。
- 视口：390px 移动端；1280px、1440px 桌面端。
- 可用性：键盘操作、焦点回收、颜色对比、点击热区和 `prefers-reduced-motion`。
- 完成后通过真实浏览器逐条执行两端核心路径，并记录无法通过的状态。

## 与后续开发的关系

- 管理端原型作为当前 `zx` / `main` 业务页面的视觉与交互参考。
- 预定端原型仅作为后续 P1 的设计储备，不能据此扩大当前接口和实现范围。
- 正式 Vue 页面仍遵循 Element Plus、Vant、UnoCSS 和现有工程约定；原型共享代码不直接复制为生产组件。
