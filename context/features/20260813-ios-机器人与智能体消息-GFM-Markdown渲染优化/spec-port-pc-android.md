# Spec：机器人/智能体消息 Markdown 渲染（PC 端 + 安卓端）

> 由 iOS 端 GFM 渲染改造（2026-08-13～14，分支 `feat/ios-gfm-markdown`，9 commit）沉淀而来。
> 本文是**行为规范**，不是实现说明：描述"渲染成什么样、交互怎么响应"，不规定用什么类、什么函数。
> iOS 的实现细节见同目录 `impl-notes.md`；本文可直接作为 PC / 安卓两端新迭代的 spec 起点。

## 1. 背景

机器人消息（`ZX:ActionCardMsg`）与智能体消息的正文是 **Markdown 与 HTML 混排**的文本。三端解析器现状：

| 端 | 解析器 | 状态 |
|----|--------|------|
| web / PC（复用 web） | `marked` 14.1.4 | 真 GFM 解析器 |
| android | Markwon 4.6.2（commonmark-java + ext-tables） | 真 GFM 解析器 |
| ios | 原为手写正则，2026-08-14 换成 cmark-gfm 0.29.4 | 本次改造 |

**所以 PC/安卓这轮不是"换解析器"**，而是把 iOS 这轮踩出来的行为规则与坑逐条对齐。解析器本身能力足够，缺的是配置、扩展与交互处理。

## 2. 目标与非目标

**目标**：三端对同一条消息的渲染结构一致（结构一致，不追像素级一致），且下面第 4~9 节的行为全部满足。

**非目标**
- 数学公式：**不做**。GFM 规范无数学语法，GitHub 是前端另挂 MathJax。要做需引 LaTeX 排版引擎，另有 `$` 与货币符号歧义、TeX 覆盖度问题。决策与评估见 `status.md` 决策记录。
- 语法高亮：代码块只给等宽字体 + 底色，不按语言着色。
- 像素级对齐其他端。

## 3. 正确性基准

<https://github.github.com/gfm/>。有歧义时以规范为准，不以某一端现有表现为准。

## 4. GFM 结构渲染要求

以下每条都是 iOS 端实测过的用例，PC / 安卓逐条自测。

### 4.1 列表
| # | 输入 | 期望 |
|---|------|------|
| L1 | 三层缩进无序列表 | 三级缩进层次分明，各级 marker 可区分（iOS 用 •／◦／▪） |
| L2 | `+ item` | 识别为无序列表 |
| L3 | `3.` 起始的有序列表 | 从 3 开始连续编号，不重排为 1 |
| L4 | `- [ ]` / `- [x]` | 渲染勾选框，不显示原始括号 |
| L5 | 有序列表内嵌无序列表 | 嵌套层级与缩进正确 |
| L6 | 列表项内含粗体/行内码/链接 | 行内样式保留 |
| L7 | 列表项内含多段落（空行 + 缩进续行） | 同项内多段，缩进对齐 |
| L8 | 紧凑列表 vs 松散列表 | 松散列表项间距更大 |

> **iOS 踩过的坑**：正文默认样式里已带段落样式（行距）时，"若已有段落样式则跳过设置缩进"的写法会让**所有缩进静默失效**。判据必须是"是否已有缩进"，不是"是否已有段落样式"。

### 4.2 表格
| # | 输入 | 期望 |
|---|------|------|
| T1 | 标准 3 列表格 | 真表格：表头底色 + 单元格边框 |
| T2 | 同一条消息含**两个**表格 | 两个都渲染 |
| T3 | 含空单元格的行 | 空格占位，列不错位 |
| T4 | 对齐符 `:---` / `:---:` / `---:` | 左/居中/右对齐生效 |
| T5 | 单元格内 `\|` 转义 | 显示字面竖线，不拆列 |
| T6 | 单元格内粗体/链接/行内码 | 行内样式保留 |
| T7 | 8 列宽表格 | **可横向滚动**查看，纵向手势仍归会话列表 |
| T8 | 表头列数与数据行列数不一致 | 按 GFM：多余单元格丢弃，缺失补空 |
| T9 | 表格紧跟段落无空行 | 正确断块 |

**表格呈现约束**
- 列宽 = 该列所有单元格自然宽的最大值，设上限（iOS 取 160pt），超出则单元格内换行
- 表头加粗 + 底色；单元格间有分隔线
- **配色不能写死浅色**：自己发的消息气泡是淡蓝底，写死的浅灰白表头会很突兀。用**半透明黑**（iOS 取表头 4%、边框 12%），叠在任意气泡底色上都协调
- 横滚容器不得吞掉纵向滚动手势

### 4.3 行内与块级
| # | 输入 | 期望 |
|---|------|------|
| I1 | `**含*星号*的粗体**` | 正确加粗，内层斜体 |
| I2 | `__粗__` / `_斜_` | 生效 |
| I3 | 中文粘连 `中文_不是斜体_中文` | 按 GFM 左右侧分隔符规则**不**变斜体 |
| I4 | 多反引号行内码 ` ``含 ` 反引号`` ` | 正确渲染 |
| I5 | 4 空格缩进代码块 | 渲染为代码块 |
| I6 | 未闭合 ``` 围栏 | 到文末结束，不吃掉后续结构（流式常见） |
| I7 | 裸 URL | autolink 成可点链接 |
| I8 | 软换行（行尾单换行） | 聊天场景按换行显示（**注意**：GFM 原义是当空格，此处为产品选择，三端需一致） |
| I9 | 空行分段 | 段落间距正确 |
| I10 | `> ` 引用块，含嵌套 | 左侧竖条 + 缩进，嵌套层次可见（iOS 用行首 `▎` 字符实现，嵌套自然叠成多根） |
| I11 | 反斜杠转义 `\*` `\_` `\|` | 显示字面字符 |
| I12 | 标题 `#`~`######` + setext 标题 | 六级字号递减；setext 亦识别 |
| I13 | 脚注 `[^1]` | 需显式启用扩展（cmark-gfm 的 `footnotes`；Markwon / marked 需确认对应插件） |

## 5. 非 GFM 但必须支持的三件事

**这三件是产品要求，规范里没有，换任何解析器都省不掉。**

### 5.1 内联 HTML
后端正文会混用 HTML，典型：

```
**<span style="color:blue;">值班总负责人：赵富文</span>**
<span style="color:orange;">午后秋阳正暖……🍂</span>
```

- 这是**合法 GFM**：CommonMark 允许内嵌 raw HTML，行内 HTML 只匹配"标签本身"，标签之间文字仍按 Markdown 解析
- 但规范只规定**原样透传到 HTML 输出**，不解析属性、不配对标签。web/PC 渲染目标就是 HTML，浏览器自动上色；**安卓/iOS 必须自己实现一个 mini HTML 渲染器**
- 后端用 HTML 上色不是乱来：Markdown 本身没有颜色语法
- 补充事实：GitHub 站点的 sanitizer 会剥掉 `style` 属性，所以同样内容在 GitHub 上并不会变蓝；web 端能变蓝是因为没接 sanitizer

**必须支持的标签**：`<span style="color:x">`（`#RGB`/`#RRGGBB`/`rgb()`/`rgba()`/CSS 命名色）、`<b>`/`<strong>`、`<i>`/`<em>`、`<u>`、`<br>`、`<p>`、`<sup>`、`<sub>`、HTML 实体解码。

**行为要求**
- `**` 与 `<span>` 叠加时，**颜色只叠加、不覆盖字体**（粗体要保留）
- 嵌套 span 就近生效（内层颜色赢），与浏览器一致
- 解析不出颜色时**只去标签、不上色**，不得把标签原文打给用户
- 实体解码必须**放在最后**，否则 `&lt;` 解出来的 `<` 会被当成标签

> PC 端注意：如果接了 sanitizer，需在白名单里放行 `style` 的 `color`，否则颜色会被剥掉。

### 5.2 引用角标（知识来源）
正文中形如：
```
……的设计理念<reference data-ref="_agent_file_doc_id_2072608869346254850"></reference>
```
- 渲染成**上标序号角标**（`[1]`），序号与消息体 `agentKnowledgeList` 顺序对齐
- **可点击**，跳到对应知识来源
- 消息底部展示知识来源列表

### 5.3 插图
正文中形如：
```
<illustration data-ref="..." data-url="https://…/xxx.jpg"></illustration>
```
- 渲染成图片，宽度按气泡内容宽，高度按原图比例
- 异步加载完成后回填并刷新气泡高度
- 可点击（iOS 首期保留入口未接图片浏览器）

> **通用做法**：这两类自定义标签解析器都不认识。**进解析器之前**把它们替换成不带任何 Markdown 语义的占位符（私有区字符 + 序号），解析渲染完成后再回填成角标/图片。占位符必须避开 `_`、`*`、`[` 等 Markdown 标点。

## 6. 流式（打字机）渲染规则

- 流式过程中正文**语法不完整**：表格可能只吐了表头、代码围栏可能没闭合
- 规则：**流式期间所有表格按等宽纯文本显示**，流结束后重新解析才成表
  - 理由：流式路径通常只有一个文本控件，中途插入表格视图会让"流式渲染"与"最终渲染"两套高度体系分叉；统一降级后高度只在流结束时跳一次
- **若做了布局/高度缓存，缓存 key 必须带 streaming 标志**，否则流结束后命中流式那份"表格是纯文本"的缓存，表格永远不成表
- 反例：每个 token 重建表格视图 → 掉帧 + 高度反复抖动

## 7. 收起 / 展开

- 长消息默认收起，底部"查看更多"
- **裁剪线不得把表格或图片切一半**：裁剪线落在表格块内时，整块要么全显示要么全不显示
- **"查看更多"遮罩渐变必须跟随气泡底色**，不能写死白色渐变——自己发的消息是淡蓝气泡，白遮罩会糊出一块白

## 8. AI 卡片判定规则（重要）

**不能只靠发送人 ID 前缀判断是不是 AI 卡片。折叠更不能绑在这条判据上。**

个人 AI 框回复推送到本人会话时，`senderUserId` 是**本人 id**（与 `targetId` 相同），没有智能体前缀。iOS 端因此出现：角标不解析、知识来源不展示。

另有一类更常见：用户把个人 AI 框长回复发到群里（`bySelf=true`，发送人是本人，`agentKnowledgeList` 为空，标题常带「【智信AI框】」）。这条**不是**「AI 卡片渲染」对象（不要拼「回复 @」、不要解析角标），但**必须折叠**。

**两套判据必须拆开**：

| 用途 | 判据 |
|------|------|
| AI 卡片渲染（角标 + 知识来源 + 「回复 @」前缀） | 消息类型为机器人卡片，且（发送人带智能体前缀 **或** `agentKnowledgeList` 非空） |
| 长卡片折叠（限高 + 「查看更多」） | 消息类型为机器人卡片（ActionCard）且超限高，**不看**发送人前缀、不看知识来源。对齐安卓 |

## 9. 交互要求

| 交互 | 要求 |
|------|------|
| 长按气泡 | 必须能弹出转发/回复菜单。**正文控件不得吞掉长按**（iOS 上 `UITextView` 默认可选中会抢走长按，需关闭文本选中） |
| 表格横滚 | 只吃横向手势，纵向仍归会话列表 |
| 角标点击 | 跳知识来源 |
| 图片点击 | 保留点击入口 |
| 链接点击 | 可点，颜色与主题色一致 |

## 10. 兜底

渲染是展示层，任何解析问题都不应让消息不可读：

1. 解析异常 → 静默回退到"纯文本显示原文"，只打日志，不给用户任何错误提示
2. 正文超长（iOS 阈值 20000 字符）→ 直接走简化路径，避免解析开销
3. 留一个**开关**，线上出问题能不发版回退

## 11. 各端实现提示

**PC（Electron，复用 web）**
- `marked` 已是 GFM，重点核对：任务列表、脚注插件、软换行配置（`breaks` 选项，需与本文 I8 一致）
- 表格容器需可横滚且不夺纵向滚动
- 若接了 HTML sanitizer，放行 `style` 的 `color`（见 5.1）
- 自定义标签 `<reference>` / `<illustration>` 建议按第 5 节的占位符思路预处理，或写 marked extension

**安卓（Markwon）**
- 已有 `ext-tables`、`html`、`linkify`。核对：任务列表（`ext-tasklist`）、脚注、`<span style="color">` 的 `TagHandler`（iOS 的行为就是照 Markwon 的 `SpanTagHandler` 对齐的，注意保持双向一致）
- Markwon 表格是 span 实现，**横滚需要单独处理**（放进 `HorizontalScrollView` 或换自绘），这是本轮 iOS 端花费最多的一块
- 自定义标签同样走占位符预处理

## 12. 验收清单

1. 第 4 节 30 条用例逐条对照（iOS 端曾建过一个 Debug 用例对照页，验完已删除；PC/安卓可仿照建临时页面）
2. 真实样本至少三条：
   - 含 `**<span style="color:blue;">…</span>**` 的值班播报
   - 含表格 + `<illustration>` + `<reference>` 的长回复（`ZX:ActionCardMsg`，发送人为本人 id）
   - 智能体流式回复（边吐边看表格从纯文本变成表格）
3. 交互：长按转发/回复、表格横滚、角标点击、收起展开
4. 配色：自己发的消息（淡蓝气泡）与收到的消息（白气泡）两种底色下都要看
5. 回归：纯文本消息与改造前无可感知差异
