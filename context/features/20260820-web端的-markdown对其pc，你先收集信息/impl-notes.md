# Impl Notes：web markdown 表格对齐 PC

> 平台无关的实现提炼。最后更新：2026-09-02
> 纯渲染层，无接口、无 bridge、无状态机。

## 1. 两套管线，改 web 展示不会惠及 PC 会话

个人 AI 框（web）用 markdown 展示组件；PC 会话卡片用另一套解析器直出 HTML。同一段正文会出现两种样子。本期只改前者的**表格**。

## 2. 气泡裁切 vs 表级横滚

气泡外壳是「超出就裁」。表格如果直接撑得比气泡宽，会被裁掉，用户滑不到。

横滚必须发生在**每一张表自己的外壳**上：外壳宽度锁在气泡内，表可以比外壳宽。不要把整段正文（标题、段落）放进同一个横滚容器，否则左右滑会把标题拖走。

不要把表格从渲染器的 DOM 里掏出来再包一层——展示组件的表格节点由编辑器内核管着，挪节点会把内部结构弄坏。

这条链还必须能在 flex 布局里收缩：子项默认 `min-width: auto` 时，不换行的表会把整列撑开，被外层裁掉、外壳却认为自己已经和表一样宽，滑条出不来。外壳和中间层都要允许缩到父级宽度（`min-width: 0` + 相对父级的 `max-width: 100%`）。

## 3. 配色：代码/引用仍半透明黑；表体白底、表头底不改

代码块、引用、边框仍用半透明黑。**表体单元格默认 `#fff`，表头底仍用原来的半透明黑，表头文字字重 600。** 这与 PC / 安卓 / iOS 消息气泡同一张 token 表的表格行。

## 4. 列宽按列数分三档（2026-09-02 定稿，三端要对齐的就是这节）

先数**首行的单元格数**，再决定列宽策略。三档互斥：

| 列数 | 表宽 | 列宽 | 横滚 |
|------|------|------|------|
| 1 | 铺满气泡可用宽 | 唯一列吃满 | 无 |
| 2 | 铺满气泡可用宽 | 按内容分配，**首列有下限**（约 5 个字宽，web 用 5em ≈ 75px @15px） | 无 |
| ≥3 | 按内容（可比气泡宽） | 每列**上限 = 半个气泡可用宽**，不定死宽——窄列仍按内容收窄 | 超出时表级横滚 |

关键点，逐条都是踩过坑得出的：

1. **≥3 列是「上限」不是「固定宽」**。定死每列半个气泡，短内容表（如 A/B/C · 1/2/3）会被撑成整行宽的空表；改成只封上限后，短表气泡自己缩回去，宽表仍是一屏两列 + 横滚。
2. **两列表首列必须给下限**。表格 auto 布局把富余宽度按各列 max-content 的比例分配，标签列（「项目/事项」）的 max-content 比正文列小一个量级，会被压到接近 min-content；中文逐字可断，min-content = 一个字宽，于是标签列每行一两个字。下限只解决这一档，不要写死百分比（35% 会让短标签白占位置）。
3. **「半个气泡」得有确定宽度可参照**。气泡本身通常是 shrink-to-fit（宽度由内容决定），拿它自己算会循环 / 塌陷。要往上找一个**宽度由父级决定**的容器——web 取整条消息行（头像 + 气泡那一层），再折算：`列上限 = 行宽 / 2 - (头像宽 + 间距 + 气泡内边距的一半)`，web 实测常量 45px，并设下限 120px 防窄屏。
4. **列宽定死时边框会被裁切边吃掉**。若某端确实要定死两列各占一半，两列合计正好等于外壳宽，第二列右边框压在横滚裁切线上，要滑一下才看得见；那种做法得让出约 16px（每列 -8px）。用「上限」方案则天然不会贴边。
5. **长文在格内折行，不要 nowrap**；配合 `word-break / overflow-wrap` 让任意位置可断，否则一格能撑出一屏。
6. **横滚只发生在表自己的外壳上**（见第 2 节），标题和段落不跟着横移。

判定用「首行单元格数」即可，GFM 表格各行列数一致。

### web 侧的实现方式（其它端不必照抄手段，照抄结果）

web 一开始用 CSS `:has()` 数列数、用容器查询单位 `cqw` 取「半个气泡」，但 PC 端 Electron 内核是 **Chrome 102**，`:has()` 要 105、`cqw` 要 105/106，整套规则在 PC 上直接失效。最终改成：

- 渲染后遍历 `<table>`，按首行单元格数打标记（`data-md-cols = 1 / 2 / 3plus`）；
- ≥3 列时按上面第 3 条算出像素值，写进 CSS 变量 `--md-cell-max`；
- 样式只认标记与变量，不依赖任何新版选择器；
- 用 MutationObserver（跟流式输出）+ ResizeObserver（跟窗口/面板宽度变化）重算，合并到下一帧。

**给原生端的等价做法**：列数与列宽上限都是「渲染前先算一遍」的事——拿到父容器宽度（或可用内容宽），按上表算出每列上限，再交给各自的表格布局。不要试图用样式表达「半个容器宽」。

原生端落地时多踩了两条（2026-09-02）：

7. **折算常量按端调，不要抄 45px。** web 从「整行」折到「半个气泡」要减头像 + 间距 + 内边距一半。desktop 头像同样 40、间距 10，但气泡内边距是 16，所以是 58。android / iOS 量列宽时拿到的已经是内容区上限（不是整行），直接 `/ 2`，不必再减头像。
8. **换绑 / 旋转要忘掉上次的宽。** 列表项会复用，上一条宽表算出的上限会漏到下一条窄气泡；高度缓存若不带可用宽，旋转后仍按旧列宽排。容器宽度一变就重算，缓存 key 也要把可用宽算进去。
9. **两列表不要用未折行自然宽。** 把第一列铺到自然宽、第二列只剩 1 个字，中文就会竖着排，表还会比外壳宽画出横条。两列都必须有约 5 字下限，剩余按自然宽比例分满可用宽，1/2 列禁止横滚。
10. **≥3 列的上限要封「整列宽」（含格内左右边距），不要先封内容再加边距。** 内容上限 = 可用宽/2 再两侧加 padding，两列合计会超过气泡大约 4 倍单侧边距，一屏就看不全两列。CSS `max-width` 写在单元格上时边距已经算进格子里；自绘表格必须把上限加在「内容 + 左右 padding」这一档。

## 4.1 段栈里表格的上下文相关间距与折叠（2026-09-02，iOS 补齐）

段栈（正文按块拆成独立视图）上有两条只在「前缀块 + 表格」这种组合里才暴露的坑：

11. **表格的上间距不能写成对前一块的固定「上收」。** 段落块的文本一般以换行收尾，文本控件测量时会多算一行空行，所以「上收 10」看着刚好；但「回复 @xx：」这类前缀块没有那行空行，同样上收就会让表格压到文字上（真机上表现为表框叠住前缀）。正确做法是**先判断前一块尾部有没有那行空行**：有就上收，没有就正向补一个固定上边距（各端取 ~16pt/dp）。间距值只有一个来源，布局、总高、折叠裁剪三处必须共用同一个函数，否则高度和实际排版会对不上。

12. **折叠裁剪对「不可切块」不能整块取舍。** 第 6 节记的「裁剪线必须落在块边界」是安卓段栈早期做法，2026-08-19 起 PC / 安卓都已改为**超限一律裁到限高**。iOS 这次才补上：原逻辑是「表格 / 引用不切半截，第一个块就超高时整块显示，否则整块不显示」，遇到「前缀一行 + 一张长表」的正文，前缀已占掉非零高度，表格便整块被丢弃——收起态只剩前缀 + 「查看更多」，看着像消息没内容。改成裁到限高后，收起态高度恒等于限高，裁剪线可能落在表格行中间，这是三端一致的有意取舍。

判据：折叠是「限高裁剪」，不是「块级取舍」；块级取舍会让不同结构的卡片折叠态高度差很多，且总有一种结构会退化成空白。

13. **折叠要挂在「消息够长」上，不能挂在「是不是 AI 卡片」上。** 定时任务推送的正文可能是普通文本消息（不是卡片类型），只有普通文本气泡没折叠的端，会把上万字整条铺开，滚十几屏才过得去。判据统一成：普通文本气泡超过限高就收起 + 「查看更多」，与卡片各走各的限高但同一套交互。要排除的只有三类——流式输出中的正文（每帧变高，会和逐帧改行高打架）、大表情、合并转发详情/聚合列表那种无气泡样式（遮罩没有底色可跟）。

14. **收起态下测到的高度不是内容全高。** 把正文控件夹到限高后，再去读它的 frame 得到的是夹后的值；写回「内容全高」就会让下一轮判成「不用折」，卡片被展平、按钮消失。全高必须用「按最大宽度重新排版一次」的量法拿（不是读 frame），并且每个会重设高度的入口（首次绑定、展开/收起、已读回执之类的重排）都要走同一条。

13. **格子改成不透明底之后，左/上边框不能只画在表格外壳上。** 为避免相邻格叠成双线，通常每格只画右+下、外壳补左+上。格子透明时能透出外壳线；格子铺实色后，第一列/第一行会把外壳线盖住，左边框像消失了。外框必须画在首列（左）和首行（上）格子自己身上。

## 5. 本期故意不对齐的

标题颜色与字号、代码块皮肤、引用、列表、单换行、折叠高度、左右渐变遮罩。输入框里用户自己插的表也不走这套展示外壳。

## 6. 内联 HTML 的 style 不是「浏览器自动上色」

个人 AI 框虽然最终是 HTML，但要进 Tiptap schema。只装了字色时，`<span style="background-color;padding;border-radius">` 会变成普通文字（或只剩字色）。背景、内边距、圆角必须做成 `textStyle` 上的属性；`background` 简写与 `background-color` 都要认。加粗 / 删除线走已有的 `font-weight` / `text-decoration` 解析，不用再写一遍。
