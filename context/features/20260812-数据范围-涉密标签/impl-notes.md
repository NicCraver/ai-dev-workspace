# Impl Notes：数据范围-涉密标签

> 平台无关的实现笔记，是其他端移植的唯一逻辑依据。web 端联调完成后必须填写。
> 写法要求：描述"逻辑"而不是"代码"——禁止出现 React/Kotlin/Swift 具体 API。

## 判定规则

- 涉密：候选清单单项 `ignoreChatType`（数值比较 `Number(x) === 1`，字段可能回传字符串 "1"，勿用严格 `=== 1`）。私聊/群聊均适用。
- 已离职：私聊 `privateInfo.leave`（同样用 `Number(x) === 1`）。群聊恒不适用。
- 两者互相独立、可共存（一个人可以同时涉密+已离职）；不共存时各自单独展示。
- 涉密/已离职不再拼进姓名文案（旧版本是姓名后缀「（已离职）」，本次改造后彻底去掉这种写法），改为独立 tag。

## Tag 视觉规格

| | 涉密 | 已离职 |
|---|------|--------|
| 文案 | 涉密 | 已离职 |
| 背景色 | `#FFF3DA` | `#E5E5E6` |
| 文字色 | `#FEAC00` | `#8F959E`（灰，取项目里已有的"次要文字灰"色板，非硬编码新色） |
| 圆角 | 2px | 2px（与涉密同一套组件/尺寸，仅换色） |
| 高度/内边距 | 与文字行内联，紧凑小尺寸（约 18px 高，横向 4px 内边距），不单独占一行 |
| 共存顺序 | 涉密在前、已离职在后，并排展示，中间留小间距（约 4px） |

姓名/群名与 tag 同一行水平排列：姓名部分弹性伸缩、超长时用标准省略号截断；tag 固定宽度不参与收缩，优先完整展示（不会被姓名挤丢或裁切）。

## 数据来源与落点覆盖

候选清单（"全量人 + 群"）一次性拉取后，在归一化阶段就把 `isSecret`/`isResigned` 算好挂在每一项上，后续所有渲染入口直接读这两个字段，不重复算判定逻辑。

需要覆盖的落点（同一份弹窗/页面内的不同 tab/区域）：
1. 「全部」列表（候选清单直出，天然带 isSecret/isResigned）
2. 「群组」列表（候选清单里群聊分区，同上）
3. 「搜索」结果列表（复用同一份候选清单做本地搜索，同上）
4. 「已选」展开的已选项 chip 列表（已选项优先从候选清单按 key 命中，同上；不在候选清单内的极端情况兜底为空，即两个 tag 都不显示）
5. 「组织架构」列表（**唯一特殊落点**）——组织架构数据来自单独的组织树接口，本身不带涉密/离职标记字段。做法：用已经拉到的候选清单（同一份"全量人+群"）建一份「账号 id → {isSecret, isResigned}」的查找表，组织架构渲染每一行时按账号 id 去查这份表回填。**这条对所有端都成立**，因为组织架构/通讯录的数据源大概率是各端各自独立的接口，都需要同样的「本地按 id 回填」思路，不要指望后端在组织树接口里加这两个字段。

若某端存在类似 web 旧版本「姓名拼已离职后缀」的历史实现，移植时一并去掉，改成独立 tag。

## 说明气泡

- 入口：弹窗/页面**标题栏**一个独立的「[涉密图标]涉密」按钮（底栏只保留「已选」，不再放涉密入口）。与行内 tag 是两个不同的东西——行内 tag 纯展示、不可点；只有这个标题栏按钮可点。
- 标题栏落点（四端对齐思路，细节按各端导航栏结构微调）：
  - web / desktop：标题栏**关闭按钮左侧**（web 通过对话框 `header-right` 插槽；desktop 宿主 modal 的 title 区域）。
  - android / iOS：标题栏**右侧**（android 各 activity 顶栏 include；iOS `rightBarButtonItem` 自定义 view）。移动端原生导航栏没有 web/desktop 那种独立关闭按钮，右侧即等效落点。
- 气泡弹出：在触发按钮**正下方居中**向下展开（不是原先底栏时代「向上顶」的算法）。气泡宽约 180–280px（端上取值不同），深色背景 `#1F2329`、文字居中。
- 箭头：android / iOS 有向上小三角（自绘，与气泡同色）；web / desktop 目前仍是无箭头纯色圆角气泡——四端箭头形态**尚未统一**，移植时按目标端既有资源取舍，不要强行照搬另一端的箭头实现。
- 交互：点击切换显示/隐藏说明气泡；点击气泡以外任意区域自动关闭；再点按钮本身也会关闭（标准 toggle 弹层）。
- 内容：固定静态文案「人力部门人员、公司全员群，聊天记录与文件涉密，不参与AI分析」，四端一致，不受选中项影响，不需要请求任何接口。

## 边界情况

- 候选清单加载失败/加载中：涉密/已离职标记跟着候选清单一起缺失，此时不展示 tag（不是展示错误态），与现有"候选清单加载失败仍可用本地数据"的降级策略一致。
- 组织架构里选中的人如果恰好不在候选清单里（理论上不应该发生，候选清单本就是"全量人"）：按空信息处理，两个 tag 都不显示，不报错。
- 「按 id 回填」的查找表必须**建一次、复用**（跟着候选清单一起构建/失效），不能在每行渲染时现场遍历整份清单——清单是"全量人+群"，量级上千，逐行线性查会让长列表滑动掉帧。
- 涉密说明入口只属于「选择数据范围」这条多选链路。若目标端的选人/选群页面同时被**单选**场景复用（如选择 AI 助理时挑一个人/群），入口必须在单选场景下隐藏，否则会出现一个点不动的死按钮；稳妥做法是入口默认隐藏、由数据范围链路显式打开，而不是默认显示再逐处关掉。
- 说明气泡是独立弹层：页面在气泡开着时被关闭/销毁，必须主动收起气泡，否则部分端会泄漏弹层窗口。

## 与 bridge 的交互

无。说明气泡是纯前端静态渲染，标记数据来自各端各自已有的"选择数据范围"候选清单接口，不涉及 WebView↔原生桥接。
