# 推送后列表刷新规则（aiBoxSendMessage → Web）

> 最后更新：2026-07-29（PC：不可见时命中当前会话延后 Chat 消息；激活时冲刷 + 只刷记忆）  
> 适用范围：web 个人 AI 框（PC `PersonalAiChat` / 移动 `MPersonalAiChatWrapper`）收到壳或原生推送后如何刷列表。  
> 角标链路见 `3端AI框角标推送.md`（本文只谈 **内容列表**，不谈黄角标数字）。  
> PC 激活/失活细节见 `20260729-pc不可见推送延后与记忆刷新/spec.md`。

---

## 1. 三层列表

```
AI框列表 (agentList)           ← POST /personalAiFrame/list
  key: agentId / belongType+belongId
        │ 选中某个 AI 框
        ▼
历史会话列表 (History)          ← POST …/getSessionList（belong 维度）
  key: session.id  ←→ 推送 sessionIds
        │ 选中某个 session
        ▼
当前消息列表 (Chat.messages)    ← POST /sessionMsg/getMessageList（sessionId）
  key: 当前 sessionId
```

推送里的 `sessionIds` = **AI 会话 id**（History / Chat 层），不是 AI 框的 `agentId`。

选择弹窗（最近联系人 / 群组 / 组织）与推送无关，**不因推送刷新**。

## 2. 三种情况怎么刷

| # | 情况 | AI框列表 `list` | 历史 History `getSessionList` | 右侧 Chat `getMessageList` |
|---|------|-----------------|-------------------------------|----------------------------|
| 1 | 无 / 空 `sessionIds` | 不刷 | 不刷 | 不刷 |
| 2 | 有 `sessionIds`，当前会话 **不在** 集合内 | **刷** | **刷** | 不刷 |
| 3 | 有 `sessionIds`，当前 `sessionId` **在** 集合内，且 **页面激活** | **刷** | **刷** | **刷**（带当前 sessionId） |
| 3b | 有 `sessionIds`，但 **页面未激活**（PC） | **延后** | **延后** | **延后**（整次 pending，激活再刷） |

说明：

- **情况 1**：壳约定账号未命中或 map 值为空时 **不通知 Web**；若仍收到空数组，直接忽略。
- **有非空 `sessionIds` 且页面激活（情况 2/3）**：中间 History **必须刷**（会话预览/排序/未读等）。
- **情况 3b（PC 不可见）**：**list / History / Chat 全都不立刻刷**（后台刷会清未读，导致入口角标一闪）；合并 pending，激活后再按 2/3 跑。
- 消息刷新按当前 `sessionId` 再拉，**不要**整页重挂 Home/Chat。
- **移动端**：无常驻可见性语义，不做 3b（始终按激活处理）。
- **desktop 壳**：个人 AI 非可见 tab 时 **不向 iframe post** `aiBoxSendMessage`（角标仍走 getBadgePushInfo）；sessionIds 本地 deferred，切回 flush。

`list` 刷新入参：沿用当前 `filterTypes` + `exemptAgentIds`，`skipGetFilter=true`（不必再打 getFilter）。

### PC 页面激活判定

`pageActive = docVisible && shellActive`

| 事件 | 效果 |
|------|------|
| 文档 `hidden` | `docVisible=false` |
| 文档 `visible` | `docVisible=true`；若已 `shellActive` 则走激活流程 |
| 壳 `aiBoxDeactivate` | `shellActive=false`（AiBrowser 切离个人 AI / 关面板） |
| 壳 `aiBoxCheckVersion` | `shellActive=true` + 激活流程 |

**激活流程（顺序）**：① 若有 pending sessionIds → 完整跑 list/History/（命中则）消息；② `getAgentDataRange` **只更新记忆栏**（不用 `getLastSessionMessage`，避免清未读）；③ 既有 build_version 验版。壳 `aiBoxCheckVersion` 双发时 web **300ms 去重**激活工作。

## 3. 接口职责（推送场景）

| 接口 | 推送时是否调用 | 说明 |
|------|----------------|------|
| `POST /personalAiFrame/list` | 情况 2、3；情况 3b 延到激活 | AI框列表 |
| `getSessionList` | 情况 2、3；情况 3b 延到激活 | 中间 History |
| `POST /sessionMsg/getMessageList` | 情况 3；情况 3b 延到激活且命中 | 右侧 Chat |
| `POST /sessionMsg/getLastSessionMessage` | 推送时不调用；**激活时也不再调用** | 会清未读；激活记忆改走 getAgentDataRange |
| `POST /agentSetDataRangeExpand/getAgentDataRange` | **PC 激活时**只取记忆回写 | 激活刷新记忆栏，不改消息列表、不清未读 |

## 4. 判定伪代码

```js
async function onAiBoxSendMessage(sessionIds, { pageActive }) {
  if (!sessionIds?.length) return // 情况 1
  if (!pageActive) {
    pendingPushSessionIds = merge(pendingPushSessionIds, sessionIds) // 情况 3b
    return
  }

  await loadAgentList({ skipGetFilter: true }) // 情况 2、3
  await refreshHistoryList({ soft: true })

  const current = currentSessionId
  if (current && sessionIds.includes(String(current))) {
    await refreshCurrentMessages(current) // 情况 3
  }
}

async function onActivate() {
  if (pendingPushSessionIds?.length) {
    const ids = pendingPushSessionIds
    pendingPushSessionIds = null
    await onAiBoxSendMessage(ids, { pageActive: true })
  }
  await refreshMemoryOnly() // getAgentDataRange → 只更新记忆
  // + 既有 build_version 验版
}
```
