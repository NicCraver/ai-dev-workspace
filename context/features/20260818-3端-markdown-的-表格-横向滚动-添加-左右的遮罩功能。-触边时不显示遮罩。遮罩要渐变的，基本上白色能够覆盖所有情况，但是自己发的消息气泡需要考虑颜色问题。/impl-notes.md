# Impl Notes：三端 markdown 表格横滚左右渐变遮罩

> 平台无关。三端都还没写代码，但显隐规则和取色原则已经定死，移植时照这里实现。

## 状态流转

每张表独立计算，不共享状态。

```
无溢出（内容宽 − 可见宽 ≤ 1）
  → 左右罩都不画

有溢出
  → 偏移 ≤ 1          → 只画右罩
  → 距右缘 ≤ 1        → 只画左罩
  → 其余              → 左右都画
```

滚动过程中实时重算，不是松手才变。容器宽度变了（窗口、旋转、折叠）也重算。

## 接口调用时序

无后端接口。

## 边界情况

| 场景 | 预期 |
|------|------|
| 窄表 | 完全无罩 |
| 一条消息多张表 | 各听各的滚动 |
| 贴左 / 中间 / 贴右 | 只右 / 双侧 / 只左 |
| 自己发的淡蓝气泡 | 罩的实色是气泡蓝，不是白 |
| 外链/微信绿气泡 | 罩跟绿，不是白 |
| 列表复用换了一条消息 | 必须重绑颜色，不能把上一张的蓝带到白气泡 |
| 流式打字机 | 期间表格是纯文本，没有横滚容器，也就没有左右罩；流结束成表后再出现 |
| 和「查看更多」上下罩重叠 | 各管各的；横滚罩不挡底部按钮 |
| 详情 / 合并转发 / 回复聚合 | 与会话同一套管线，行为一致 |

## 错误处理策略

遮罩是纯装饰。算错或画失败时最差就是没有提示条，不影响滚动、长按、发送。不要因为遮罩逻辑抛错让整条消息渲染失败。

## 联调坑

- **写死白色渐变叠淡蓝气泡会糊一块白。** 上一轮 iOS「查看更多」已经踩过。左右罩必须跟**当前这条气泡的真实底色**，三端底色 hex 并不完全相同，不要为了对齐绝对值而抄另一端的色值。
- **遮罩不能进滚动内容层。** 进了就会跟着单元格一起跑，失去「贴在视口边缘」的效果。画在视口上（外壳层 / dispatchDraw 按视口坐标 / sticky 在 overflow 容器）。
- **不要另叠可点的遮罩控件。** 会吃横滚和长按。要么 `pointer-events: none`，要么只在绘制阶段画、不进命中树。
- **安卓列表复用：** 每次绑定含表消息都要重设罩色，字段留在控件上会串色。
