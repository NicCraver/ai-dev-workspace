# Impl Notes：三端 markdown 表格横滚

> 平台无关。2026-08-19 产品改口：去掉左右渐变罩，宽表横滚条溢出即常驻。

## 状态流转

每张表独立计算，不共享状态。

```
无溢出（内容宽 − 可见宽 ≤ 1）
  → 不画横滚条，下边距保持基线（表底 8px）

有溢出
  → 立刻画出横滚条（不等用户先滑一次）
  → 条贴近表底；条到后文 / 气泡底的空隙加在容器外侧
  → 滑的过程中拇指跟着走
  → 松手后条仍在，不淡出
```

容器宽度变了（窗口、旋转、折叠）也重算。不再根据贴左/贴右画渐变罩。

## 接口调用时序

无后端接口。

## 边界情况

| 场景 | 预期 |
|------|------|
| 窄表 | 完全无条，下边距不额外加大 |
| 一条消息多张表 | 各算各的溢出 |
| 自己发的淡蓝 / 外链绿气泡 | 条是半透明黑，不跟气泡换色 |
| 列表复用 | 没有罩色可串；条按当前内容宽重算 |
| 流式打字机 | 期间表格是纯文本，没有横滚容器，也就没有条；流结束成表后再出现 |
| 和「查看更多」上下罩重叠 | 各管各的；横条贴表底 overlay，不挡底部按钮 |

## 错误处理策略

横条是纯装饰。算错或画失败时最差就是没有提示条，不影响滚动、长按、发送。不要因为指示条逻辑抛错让整条消息渲染失败。

## 联调坑

- **系统滚动条各端观感差太多。** 安卓 ROM 自带条又粗又黑；iOS 系统 indicator 只在滑动时闪一下、松手就没。要「默认直接显示、常驻」，三端都得自己画（或 PC 显式写 `::-webkit-scrollbar` 高度，否则 Chromium overlay 条只在滑/悬停时出现）。
- **compileSdk 28 没有 `setHorizontalScrollbarThumbDrawable`。** 安卓只能在 `dispatchDraw` 里自绘。
- **左右渐变罩已撤销。** 原先罩必须跟气泡真实底色、透明端必须同色 alpha=0，那些坑随罩一起作废，代码里不要再留 `fadeColor` / `--md-table-fade-color`。
- **遮罩不能进滚动内容层**——这条在撤罩之后不再适用。横条仍必须画在滚动内容**之上、视口坐标**，进了内容层会跟着单元格一起跑。
- **滚动容器的内边距会落在内容与横条之间。** 要「条贴近表、条下多留空」，内边距应收、空加在容器外侧。把空加在内边距上，看起来就是条被从表底推开。
